## Scope and fixed protocol

Use the existing OAS4 training/validation split in
`data/processed/processed_oas_multi.json`, SHA-256
`bd854ae32de886bc9b4466edf5d1aa3ade6c09847b622ceaa60cba395bbd5ad8`.
The test partition is excluded from checkpoint selection and generation.
Keep max length 384, two-residue anchor trimming, up to 20 epochs, patience 3,
and checkpoint selection by teacher-forced core accuracy. Training dropout is
disabled in evaluation. ESM-2 retains LR `3e-5`, warmup `0.06`, weight decay
`0.01`, microbatch 4 and accumulation 8; scratch retains LR `1e-4`, no warmup
or weight decay, and batch 32. The LR candidate `1e-4` is not combined with
ESM-2 dropout in this experiment.

Generation uses the same 150 validation frameworks selected with seed 42,
without length stratification, and 20 candidates per framework: temperature 1,
top-p 0.9, top-k 0, natural EOS with a 97-token decode cap. Native loop length
is available to scoring only. The primary comparison is native edit similarity
over valid candidates, averaged within each framework and then over frameworks.
Report validity and contributing populations beside it. Supporting endpoints
are length-match rate and capped length MAE, diversity, conditional core/anchor
recovery and their populations, and IgBert judge perplexity/coverage.

The IgBert judge always receives partner context, independently of the generator.
Its cached revision is `81a4abb8a4dac5cdcbefc28e5b331a82224c485d`. Judge
perplexity is a supporting endpoint because of OAS pretraining overlap; these
experiments measure sequence generation and robustness, not binding function.

## Six no-partner controls

[`20261006_no_partner_controls.json`](20261006_no_partner_controls.json) trains
scratch AR, scratch S2S and ESM-2 S2S at seeds 42/43 with no partner context and
dropout 0. Generation also omits partner context; the judge includes it.
Each checkpoint writes one `generation_eval.json`. This is the control for the
September screen's partner-absent evaluations, where models were trained with
partner context at dropout 0 or 0.5. Supplying a partner to a model trained
without one would be an additional distribution-shift experiment and is outside
this control batch.

## Commands for the user

Review and commit the status/documentation updates before launching so the new
runs record a clean source revision. Start confirmation in a fresh batch
directory; the launcher creates a timestamped directory automatically. Do not
reuse a September batch or the completed no-partner batch. The current source
fingerprint differs from the frozen control plan after the evaluation cleanup.

From the repository root, check the environment and inspect the next plan:

```bash
cd /mnt/hdd/pang/CDRSeqGen
conda activate cdrprj
unset EXPERIMENT_DIR SWEEP_DIR
nvidia-smi
HF_HUB_OFFLINE=1 CUDA_VISIBLE_DEVICES=0 python scripts/check_environment.py cdrprj
DRY_RUN=1 HF_HUB_OFFLINE=1 ./scripts/run.sh 0 spec configs/experiments/20261006_esm2_dropout_confirmation.json
```

Then launch the four confirmation runs:

```bash
HF_HUB_OFFLINE=1 ./scripts/run.sh 0 spec configs/experiments/20261006_esm2_dropout_confirmation.json
```

GPU 0 was idle during the October 7 check; GPU 1 was busy. Recheck availability
before launching. Each GPU executes its assigned trials sequentially. Keep the
same source and environment throughout this confirmation batch.

Completion requires four `completed` rows in `runs.tsv` and eight generation
files: with and without generator partner context for each checkpoint. Each
file should contain the same 150 framework identities, up to 3,000 valid
candidates, and recorded validity and judge coverage. `batch_tables.md` and the
dashboard should retain all four trials and both generator context regimes.

If this new batch is interrupted, set `CDR_CONFIRMATION_BATCH` to **its printed
directory** and resume without changing source, data, configs or protocol:

```bash
EXPERIMENT_DIR="${CDR_CONFIRMATION_BATCH:?Set to the printed confirmation batch directory}" HF_HUB_OFFLINE=1 ./scripts/run.sh 0 spec configs/experiments/20261006_esm2_dropout_confirmation.json
```

The launcher skips compatible completed trials. An unfinished trial restarts
training from its configuration; optimizer-checkpoint recovery is not automatic.
